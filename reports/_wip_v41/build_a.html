Build specification

This section is what a build job works from. It replaces the design table of version 4 wherever the two differ, and the review gives the reason for each difference. Values marked param come from the parameter table and are frozen before the trusted-setup ceremony. Names are working names.

Conventions

ItemDefinition
FieldThe BN254 scalar field. Every hashed value is less than its modulus p, and the contracts reject inputs that are not
HashPoseidon with circomlib's parameters. H2, H3 and H4 take two, three and four inputs. On-chain they are three stateless bytecode contracts generated from the same parameters, checked against the circuit with shared test vectors

Reward indexOne number G for the whole pool, at most 90 bits, fixed-point with 64 fractional bits. It only grows
TreeAppend-only, depth 32, nodes H2(left, right), empty leaf ZERO = keccak256("murmuration.zero") mod p. One leaf per transaction: leaf = H4(C0, C1, C2, C3), a bundle of four note commitments. The pool keeps the last 64 roots
Positionpos = 4 × leafIndex + slot, where slot is 0 to 3. It identifies one note for good
EpochsA screening epoch is 7,200 blocks. A reward checkpoint is taken every 300 blocks. A cap step is 648,000 blocks, about 90 days. All count from the pool's genesis block param

Keys, notes and addresses

// Keys. sk never leaves the wallet.
spk      = H2(TAG_SPK, sk)                 // proves the right to spend
nk       = H2(TAG_NK,  sk)                 // computes nullifiers; safe to give to a view-only wallet
ownerPk  = H4(TAG_PK, spk, nk, d)          // d: a diversifier, so one wallet can hand out many unlinkable addresses

// A note is (asset, value, accrued, index, ownerPk, rho). rho is 248 random bits.
ownerCommit = H3(TAG_OC, ownerPk, rho)     // hides the owner; this is all a deposit reveals about its recipient
packed      = TAG_NOTE·2^200 + accrued·2^104 + value·2^8 + asset
commitment  = H3(packed, index, ownerCommit)
nullifier   = H4(TAG_NF, nk, pos, rho)     // one per note position; published when the note is spent

// Address a payer needs: ownerPk (32 bytes) and the recipient's X-Wing public key (1,216 bytes).
// Short form: ownerPk and keccak256(key). The key is announced once through Pool.announce and read from the public snapshots.
  • accrued is reward already earned and not yet turned into tokens. It travels with the note. index is the value of G when the note was created.
  • Encryption. Output 0 is encrypted to the recipient with HPKE over the X-Wing hybrid of X25519 and ML-KEM-768: 1,120 bytes of key encapsulation, an 80-byte payload and a 16-byte tag, 1,216 bytes in all. Output 1 is the sender's change, sealed with the sender's own symmetric key: 96 bytes. The relayer's fee note is opened to the relayer off-chain. The reward note is derived by its owner. Every spend therefore publishes the same 1,312 bytes of ciphertext whatever it does.
  • The pool does not check ciphertexts. A sender who posts garbage loses the payment for the recipient and gains nothing. This is the same in every shielded pool.
  • Not post-quantum: the Groth16 proof. Ownership and nullifiers rest on hashes only.

The circuit

There is one circuit, Spend. It takes two notes of one asset and one owner, and produces three notes of the same asset, one note of the reward token, and an optional public amount. A private transfer has a public amount of zero. A withdrawal has a standard size as its public amount. A deposit needs no proof: the pool computes the commitment itself from public values. Estimated size is about 22,000 constraints, which is to be measured by the build job, as is proving time on a mid-range phone.

Constraints

  1. Keys. spk and nk are derived from sk as defined above.
  2. Asset. asset is one of the listed ids, and weight is that asset's constant from the table. The reward token's weight is zero.
  3. Ranges. Every value, accrued, claim and publicAmount fits in 96 bits. gRef and each input's index fit in 90 bits. Each leafIndex fits in 32 bits and each slot in 2. Path selectors are bits.
  4. Input notes. For each input, ownerPk, ownerCommit, packed and commitment are computed from spk, nk and the note's contents exactly as defined above.
  5. Membership. For each input, the commitment placed at slot among others hashes to a leaf, and that leaf with leafIndex and path hashes to root. The check is skipped only when the input's value and accrued are both zero, which is how a wallet pads a spend that has one real input.
  6. Nullifiers. nf[i] = H4(TAG_NF, nk, 4 × leafIndex + slot, rho) for each input, from the same leafIndex, slot and rho used above.
  7. Index order. gRef − index is between 0 and 290 for each input. A note cannot be spent against a checkpoint older than itself.
  8. Reward earned. earned = floor(weight × (value₀ × (gRef − index₀) + value₁ × (gRef − index₁)) / 2^64), enforced as an exact division with a 64-bit remainder.
  9. Outputs. C[k] = H3(packed(asset, valueₖ, accruedₖ), gRef, ownerCommitₖ) for k in 0 to 2.
  10. Reward note. C[3] = H3(packed(TOKEN, claim, 0), gRef, ownerCommit₃).
  11. Value is conserved. The two input values add up to the three output values plus publicAmount.
  12. Reward is conserved. The two input accrued amounts plus earned add up to the three output accrued amounts plus claim.
  13. The public asset is the real one. publicAmount × (asset − publicAsset) = 0.
  14. Binding. extHash takes part in one constraint so that no tool can drop it from the proof.

What the circuit leaves to the contract: that the root is recent, that the nullifiers are new and distinct, that gRef is a real checkpoint, that the public amount is a standard size the asset can pay, and that extHash matches the call.

What the proofs must show

The launch gate requires each of these to be machine-checked against the compiled circuit, with the statement published in plain words beside the formal one.

  1. No value is created. Any accepted spend takes out exactly what its inputs held, and each input with a non-zero value or reward is a note in the tree.
  2. No note is spent twice. A note position and a key give exactly one nullifier, and a nullifier names at most one note position per key.
  3. No reward is created. Reward leaving a spend is at most the reward entering plus weight × value × (gRef − index) / 2^64 for each input, rounded down.
  4. Nothing is left free. Given the private inputs, every public output is determined. No signal can take two values.
  5. No wrap-around. No sum or product in constraints 8, 11 and 12 can reach the field modulus.
