## Key Question 1 — Fusaka (shipped 3 Dec 2025): final EIP list, parameters, blob schedule, current gas limit

### Takeaway
Fusaka (Fulu/Osaka) activated on mainnet at epoch 411392 on 2025-12-03 21:49:11 UTC with nine core EIPs plus four supporting EIPs; the two blob-parameter-only forks followed (BPO1 2025-12-09 → 10/15 blobs; BPO2 2026-01-07 → 14/21 blobs). The transaction gas cap is exactly 2^24 = 16,777,216; the secp256r1 precompile is at 0x100 for 6,900 gas; the mainnet gas limit has been ~60M since 2025 and remains ~60M as of October 2026, with 200M attached to the (now-postponed) Glamsterdam Hoodi fork.

### Cited Findings

**Fork meta and activation**
- EIP-7607 (Fusaka Hardfork Meta) lists Core EIPs: EIP-7594 (PeerDAS), EIP-7823 (upper bounds for MODEXP), EIP-7825 (Transaction Gas Limit Cap), EIP-7883 (ModExp gas cost increase), EIP-7917 (deterministic proposer lookahead), EIP-7918 (blob base fee bounded by execution cost), EIP-7934 (RLP execution block size limit), EIP-7939 (CLZ opcode), EIP-7951 (secp256r1 precompile); "Other EIPs": EIP-7892 (Blob Parameter Only hardforks), EIP-7642 (eth/69, drop pre-merge fields), EIP-7910 (eth_config JSON-RPC), EIP-7935 (set default gas limit to 60M). — [EIP-7607](https://eips.ethereum.org/EIPS/eip-7607)
- Mainnet activation: epoch 411392, timestamp 1764798551 = 2025-12-03 21:49:11 UTC, fork ID 0x5167e2a6. Testnets: Holešky epoch 165120 (2025-10-01), Sepolia epoch 272640 (2025-10-14), Hoodi epoch 50688 (2025-10-28). — [EIP-7607](https://eips.ethereum.org/EIPS/eip-7607)
- The EF mainnet announcement gives the same activation (slot 13,164,544, 2025-12-03 21:49:11 UTC) and says EIP-7825 "sets a protocol-level transaction gas limit of 16,777,216" and EIP-7951 "enables integration with secure hardware such as Apple Secure Enclave, Android Keystore, and FIDO2/WebAuthn devices"; EIP-7935 raises the default gas limit to 60M. — [EF: Fusaka mainnet announcement](https://blog.ethereum.org/2025/11/06/fusaka-mainnet-announcement)

- BPO1 mainnet: epoch 412672, timestamp 1765290071 = 2025-12-09 14:21:11 UTC, fork ID 0xcba2a1c0. BPO2 mainnet: epoch 419072, timestamp 1767747671 = 2026-01-07 01:01:11 UTC, fork ID 0x07c9462e. — [EIP-7607](https://eips.ethereum.org/EIPS/eip-7607)

- EIP-7892 (Final, Informational) defines BPO forks as hard forks that modify only `target`, `max`, and `baseFeeUpdateFraction`. — [EIP-7892](https://eips.ethereum.org/EIPS/eip-7892)
- EIP-7918 (Final): adds a reserve price `BLOB_BASE_COST * base_fee_per_gas` to blobs with `BLOB_BASE_COST = 2**13` (8192); when the reserve price exceeds `GAS_PER_BLOB * base_fee_per_blob_gas`, `calc_excess_blob_gas()` no longer subtracts target blob gas, so the blob base fee cannot fall far below execution cost. — [EIP-7918](https://eips.ethereum.org/EIPS/eip-7918)

**Per-EIP parameters**
- EIP-7825 (Final): "Transactions specifying gas limits higher than 16,777,216 gas will be rejected"; cap is 2^24 and applies regardless of block gas limit; such txs are excluded from the txpool and a block containing one is invalid; example error code `MAX_GAS_LIMIT_EXCEEDED`. — [EIP-7825](https://eips.ethereum.org/EIPS/eip-7825)
- EIP-7951 (Final, created 2025-05-27): precompile address `0x100`; gas 6,900 (vs 3,000 for ECRECOVER; benchmarks showed P-256 verification significantly slower); input 160 bytes = hash ‖ r ‖ s ‖ qx ‖ qy (32 bytes each); output 32-byte value 1 on success, empty on failure; failures must not revert and charge the same gas. It "supersedes RIP-7212" with the same address/IO but fixes two issues (point-at-infinity check; x-coordinate comparison mod n). RIP-7212 charged 3,450 gas, so the EIP notes the gas difference "breaks L2 gas compatibility". — [EIP-7951](https://eips.ethereum.org/EIPS/eip-7951)
- EIP-7823 (Final): each MODEXP length input (base, exponent, modulus) must be ≤ 8192 bits (1024 bytes); larger inputs make the precompile fail and consume all gas; still allows RSA verification up to 8192-bit keys. — [EIP-7823](https://eips.ethereum.org/EIPS/eip-7823)
- EIP-7883 (Final): ModExp (address 0x05) gas = `max(500, floor(multiplication_complexity * iteration_count))` (minimum raised from 200 to 500); `multiplication_complexity = 16` if max(base_len, mod_len) ≤ 32 else `2 * words**2` (words = ceil(max_len/8)); iteration count for exponent_length > 32 is `16 * (exponent_length - 32) + bitlen(low 256 bits) - 1` (previously 8×). — [EIP-7883](https://eips.ethereum.org/EIPS/eip-7883)
- EIP-7934 (Final): protocol-level cap on RLP-encoded execution block size of 10 MiB, "which includes a margin of 2 MiB to account for beacon block sizes". — [EIP-7934](https://eips.ethereum.org/EIPS/eip-7934)
- EIP-7939 (Final): new opcode CLZ at `0x1e`; pops x, pushes number of leading zero bits (256 if x == 0); rationale benchmarks CLZ as costing approximately the same compute as ADD (the spec text fetched did not state the numeric gas tier explicitly — see Gaps). — [EIP-7939](https://eips.ethereum.org/EIPS/eip-7939)
- EIP-7917 (Final): pre-calculates a deterministic `proposer_lookahead` for the next MIN_SEED_LOOKAHEAD + 1 epochs at each epoch start. — [EIP-7917](https://eips.ethereum.org/EIPS/eip-7917)
- EIP-7935 (Final, Informational): "The gas limit on mainnet is currently 36M. This should be significantly increased to 60M by the time Fusaka is released by execution layer clients updating their default configurations." — [EIP-7935](https://eips.ethereum.org/EIPS/eip-7935)

### Inferences
- For a privacy protocol: a single transaction can never carry more than 16,777,216 gas on L1 post-Fusaka, so batch relayer transactions (many ZK verifications/withdrawals per tx) must be sized under this cap; EIP-8037 (Glamsterdam, below) would add a separate "state gas" dimension that is *not* subject to the 2^24 cap but is capped by `tx.gas ≤ 2^32−1`.
- P-256 (passkey/WebAuthn) verification is a Final mainnet primitive at 0x100 for 6,900 gas, enabling passkey-based spend authorization without a Solidity P-256 library (~200k+ gas historically); L2s that implemented RIP-7212 at 3,450 gas differ in cost, not interface.
- The ModExp repricing (min 500 gas; heavier exponents for >32-byte exponents) and 1024-byte bound affect RSA-based or ModExp-heavy verifiers; BN254 pairing precompiles (0x06–0x08) were not repriced in Fusaka (no EIP in EIP-7607 touches them).

### Gaps
- BPO2's exact `baseFeeUpdateFraction` was not found in a primary source fetched (EIP-8134 covers only BPO1; EF post omits fractions). Client configs (e.g. go-ethereum `params/config.go`) would hold the value.
- The numeric gas tier of CLZ (EIP-7939) was not extracted from the page text (the page says it costs about the same compute as ADD; the "Gas cost" rationale section does not state a number in the portion captured). Check the EIP page's Specification section directly.
- No primary-source confirmation of validator-signalled gas-limit distribution (gaslimit.pics breakdown was truncated); only the ~60M "latest" value as of 6 Oct 2026.
- EIP-7642 and EIP-7910 pages were not fetched (networking/RPC only).

## Key Question 2 — Glamsterdam: headliners, full SFI list, parameters, target gas limit, dates, devnet/testnet status

### Takeaway
Glamsterdam (Amsterdam EL / Gloas CL) has 18 SFI core EIPs headlined by ePBS (EIP-7732) and Block-Level Access Lists (EIP-7928), plus a large gas-repricing package (EIP-2780, 7976, 7981, 8037, 8038, 7778) and developer-facing changes (EIP-7708 ETH transfer logs, EIP-7954 64 KiB contracts, EIP-7997 deterministic factory, EIP-7843 SLOTNUM, EIP-8024 SWAPN/DUPN/EXCHANGE, EIP-8246). It forked Sepolia on 2026-10-06 (epoch 353024), but the Hoodi fork (set for 2026-10-26) was postponed on 22 Oct 2026 and on 6 Nov 2026 ACD paused the hard-fork process entirely pending resolution of "eight gas invariants" that EIP-8037/8038 break in deployed contracts; no mainnet date exists and the ethereum.org "Q4 2026" target predates the pause.

- EIP-8037 (State Creation Gas Cost Increase): `CPSB = 1530` gas per new state byte, derived from a 120 GiB/yr state-growth target at a 150M reference gas limit; `STATE_BYTES_PER_STORAGE_SET = 64` → new storage slot = 97,920 state gas; `STATE_BYTES_PER_NEW_ACCOUNT = 120` → new account = 183,600 state gas; `STATE_BYTES_PER_AUTH_BASE = 23` → 7702 delegation indicator = 35,190 state gas; contract code deposit = 1,530 state gas per byte (24,576-byte contract ≈ 37,784,880 state gas); `TX_MAX_TOTAL_GAS_LIMIT = 2^32 − 1`; `TX_MAX_GAS_LIMIT` (EIP-7825, 16,777,216) applies to execution gas only; state gas comes from a `state_gas_reservoir = evm_gas − gas_left` first, then from `gas_left`; block `gas_used = max(block_execution_gas_used, block_state_gas_used)`; `SYSTEM_CALL_GAS_LIMIT = 30,000,000 + 64×1530×16 = 31,566,720`; `SYSTEM_MAX_SSTORES_PER_CALL = 16`. — [EIP-8037](https://eips.ethereum.org/EIPS/eip-8037)

### Inferences
- The repricing package materially raises cost for state-heavy privacy contracts: each new nullifier slot (SSTORE 0→x) would cost 97,920 state gas (EIP-8037) in addition to 10,000 STORAGE_WRITE + 2,100 cold access (EIP-8038) — several times today's ~22,100. Merkle-tree insertions that write many fresh slots, and shielded-pool "note" commitments stored on-chain, are most exposed; appending to event logs (EIP-7708-style) is not repriced.
- Contracts that hardcode gas (e.g. `call{gas: X}`, `gasleft()` checks in relayer refund logic, 2300-stipend assumptions) are exactly the "gas invariants" the EF is auditing; relayer fee-estimation and multisig execution paths should be reviewed against https://github.com/ethereum/glamsterdam-gas-invariants.
- 64 KiB contracts (EIP-7954) allow larger monolithic ZK verifiers (e.g. multiple verifying keys in one contract) without proxy splitting, but code deposit would cost 1,530 state gas/byte (a 64 KiB deploy ≈ 100M state gas, which is only payable because state gas is not subject to the 2^24 execution cap).
- EIP-7708 gives light-client/indexer code a uniform way to detect ETH flows into/out of a shielded pool via logs, but it also makes every ETH value transfer (including from relayers to users) show up as a Transfer-style log — a privacy-linkability consideration.
- Timing: with the Hoodi fork paused on 6 Nov 2026 and spec changes to EIP-8037/8038 still possible, a Q4 2026 mainnet is no longer realistic; Q1 2027 or later is the practical expectation (inference; no primary source gives a new date).

**EIP-8141 Frame Transaction (Draft; created 2026-01-29; requires EIP-7702 among others)**
- New tx type `FRAME_TX_TYPE = 0x06`; a transaction is a sequence of up to `MAX_FRAMES = 64` frames, each with `mode` (DEFAULT=0, VERIFY=1, SENDER=2), `flags` (bits 0–1 approval scope; bit 2 = atomic batch `0x4`), `target`, `limits` (execution and state gas), `value`, `data`. `ENTRY_POINT = address(0xaa)` with a new `APPROVE` instruction (`0xaa`). `FRAME_TX_INTRINSIC_COST = 12000`, `FRAME_TX_PER_FRAME_COST = 475`; execution and state gas metered in separate pools per EIP-8037; single `max_fee` covers execution, state and blob gas. Signature schemes: `ARBITRARY`, `SECP256K1`, `P256`. Nonce rule `tx.nonce == state[tx.sender].nonce`, incremented when payment is approved. Frame targets with a 7702 delegation indicator execute under 7702 semantics; the 7702 authorization list is omitted "because it relies on ECDSA". Enables key rotation, PQ signatures, native batching and "alternative fee payment without third-party relayers". — [EIP-8141](https://eips.ethereum.org/EIPS/eip-8141)

**EIP-8250 Keyed Nonces for Frame Transactions (Draft; created 2026-04-16; authors incl. Thomas Thiery, Toni Wahrstätter, lightclient, Vitalik Buterin; requires 7928, 7976, 8037, 8038, 8141)**
- Replaces the single nonce with `nonce_keys` (bounded, strictly increasing list of 256-bit keys, `MAX_NONCE_KEYS = 16`) and `nonce_seq` (64-bit, shared by selected keys); empty list = legacy nonce; keys live in `NONCE_MANAGER = 0x8250968C12e01A19d6F667b9B2F3b3A4d0e51cB7` (deployed by keyless tx); `MAX_NONCE_SEQ = 2^64 − 1` marks keys single-use; nonce consumption happens at payment approval (atomic even if later frames revert); `KEYED_NONCE_FIRST_USE_STATE_GAS = 97,920` (under EIP-8037), `KEYED_NONCE_ACCESS_COST = 12,100` per key (under EIP-8038) added to intrinsic gas and calldata floor; new TXPARAM indices 0x0D–0x10. Motivation explicitly names privacy protocols that "route many users through a shared sender to avoid public linkage", nullifier-derived keys, smart-wallet session keys, relayer-style senders; the EIP itself keeps the one-pending-tx-per-sender mempool rule but removes the protocol obstacle to relaxing it. `FORK_TIMESTAMP` TBD; must activate at/after EIP-8141. — [EIP-8250](https://eips.ethereum.org/EIPS/eip-8250)

### Inferences
- For a shielded pool: EIP-8141 + EIP-8250 are the protocol's intended replacement for relayers — a pool contract (or user account) can be the `sender` whose VERIFY frame checks a ZK proof and whose payment frame pays fees from pool funds, with nullifier-derived nonce keys allowing many concurrent withdrawals from one sender. This is explicitly the motivation in EIP-8250. None of this is live before Hegotá (ethereum.org: Q2 2027, unconfirmed), so relayers remain necessary through at least mid-2027.
- EIP-8151 would break any design that relies on `ecrecover` returning an address that currently has contract code (e.g. verifying a signature "from" a contract address); 7702-delegated EOAs remain fine.
- EIP-8182 being declined (twice: meta EIP and tier list) means there is no planned L1-native shielded pool; the EF's stated preference is for competing application-layer schemes using Frames — favourable for independent privacy protocols.
- EIP-8131 would charge 7702 authorization tuples and blob hashes at the floor; relayers batching many 7702 auths would see higher floor gas.

### Gaps
- No primary source for Hegotá devnet dates or CFI→SFI decision calendar beyond the Feb 2026 headliner window; ethereum.org's "Q2 2027" is the only official timing and is labelled unconfirmed.
- Whether FOCIL ships as "same-slot" is only supported by an undated design note; the EIP-7805 text fetched did not state the final choice. "Big FOCIL" terminology was not found in any source.
- The EIP-8141 page was only read to 100,000 of 121,585 characters; the tail (test cases/security) was not read. EIP-8141's spec is flagged in secondary coverage as still subject to change.
- Discrepancy between EIP-8081 (EIP-8025 DFI) and the EF tier list (EIP-8025 A-tier) is unresolved.

### Inferences
- A ZK verifier that relies on BLS12-381 pairings can use 0x0f at 32,600k + 37,700 gas (e.g. 2 pairs = 102,900 gas), already live; no Poseidon precompile will exist on L1 in the foreseeable future, so Poseidon-based Merkle trees remain pure-EVM (or move to Keccak/SHA-256/BLAKE where a precompile or cheap opcode exists).
- The EF's hash pivot means EIP-7864's eventual hash is more likely Keccak/BLAKE3/SHA-256 than Poseidon2; privacy protocols that planned to prove L1 state inclusion in SNARK-friendly fields should not assume a Poseidon state tree.

- PQ: no PQ signature precompile ships before milestone J* (post-Hegotá); account-level PQ migration is expected to route through EIP-8141 signature agility rather than a new precompile in Hegotá (EIP-8355 DFI).

## Key Question 5 — What breaks or reprices existing patterns

### Takeaway
Nothing in Fusaka changed opcode gas other than ModExp, but it capped per-tx gas at 16,777,216 and bounded ModExp inputs. Glamsterdam (date now open) is the breaking fork: SSTORE new-slot, account creation, code deposit and cold access all get more expensive (EIP-8037/8038/2780), calldata floor doubles-plus (EIP-7976), refunds stop counting toward block gas (EIP-7778), max code size goes to 64 KiB (EIP-7954), the 0x4e59… CREATE2 factory becomes canonical (EIP-7997), ETH transfers emit logs (EIP-7708), and SELFDESTRUCT's residual burn is removed (EIP-8246). EOF is Stagnant (EIP-7692) and not in any fork; precompile addresses are unchanged (new ones only at 0x100 and 0x0b–0x11); blob fees got a floor via EIP-7918 and BPO forks raised throughput to 14/21.

### Cited Findings
- SELFDESTRUCT: EIP-6780 (Cancun) left burns only for same-tx-created contracts; EIP-8246 (Glamsterdam SFI) removes that remaining burn; EIP-4758 "Deactivate SELFDESTRUCT" is CFI for Hegotá and A-tier in the EF list. — [EIP-8246](https://eips.ethereum.org/EIPS/eip-8246); [EIP-8081](https://eips.ethereum.org/EIPS/eip-8081); [EF tier list](https://blog.ethereum.org/2026/09/07/protocol-hegota-eips)
- SLOAD/SSTORE/CALL/BALANCE/EXT* repricing: EIP-8038 (Glamsterdam) — cold account access 3,000; STORAGE_WRITE 10,000; ACCOUNT_WRITE 9,000; CREATE_ACCESS 12,000; refund for clear 11,616; EXTCODESIZE/EXTCODECOPY second DB read charged. New state: EIP-8037 — 97,920 state gas per new slot, 183,600 per new account, 1,530 per code byte. — [EIP-8038](https://eips.ethereum.org/EIPS/eip-8038); [EIP-8037](https://eips.ethereum.org/EIPS/eip-8037)
- Refunds: EIP-7778 (Glamsterdam) stops refunds reducing block gas accounting; EIP-3298 (remove storage-clear refund entirely) is CFI for Hegotá/A-tier. — [EIP-7778](https://eips.ethereum.org/EIPS/eip-7778); [EIP-8081](https://eips.ethereum.org/EIPS/eip-8081)
- Calldata/access lists: EIP-7976 (floor 64/64) and EIP-7981 (access-list bytes priced) in Glamsterdam; EIP-8131 (unified 64-gas floor incl. 7702 auths and blob hashes) CFI Hegotá. — [EIP-7976](https://eips.ethereum.org/EIPS/eip-7976); [EIP-7981](https://eips.ethereum.org/EIPS/eip-7981); [EIP-8131](https://eips.ethereum.org/EIPS/eip-8131)
- Intrinsic gas: EIP-2780 decomposes 21,000 into 12,000 base + 3,000 cold access + 6,000 value cost; new-account recipients pay 183,600 state gas; 7702 auth = 7,816 execution + 35,190 state gas. — [EIP-2780](https://eips.ethereum.org/EIPS/eip-2780)
- Logs: no LOG repricing EIP found in EIP-7607/7773/8081; EIP-7708 adds protocol-generated Transfer logs from `0xff…fe`; EIP-7668 (remove bloom filters) is CFI/C-tier for Hegotá. — [EIP-7708](https://eips.ethereum.org/EIPS/eip-7708); [EIP-8081](https://eips.ethereum.org/EIPS/eip-8081)
- Precompiles: ModExp repriced/bounded (EIP-7883/7823, Fusaka); hash-function repricing EIP-7667 is Stagnant; EIP-7666 "EVM-ify the identity precompile" DFI in EIP-8081 (C-tier in EF list); ecRecover semantics change proposed in EIP-8151 (CFI/A-tier Hegotá). New precompile addresses: 0x100 (P-256, Fusaka), 0x0b–0x11 (BLS12-381, Pectra). No address changes to existing precompiles found. — [EIP-7883](https://eips.ethereum.org/EIPS/eip-7883); [EIP-7667](https://eips.ethereum.org/EIPS/eip-7667); [EIP-8081](https://eips.ethereum.org/EIPS/eip-8081); [EIP-7951](https://eips.ethereum.org/EIPS/eip-7951); [EIP-2537](https://eips.ethereum.org/EIPS/eip-2537)
- CREATE2: EIP-7997 (Glamsterdam SFI) formalises the Arachnid-style factory at 0x4e59b44847b379578588920cA78FbF26c0B4956C; CREATE/CREATE2 pay CREATE_ACCESS 12,000 (EIP-8038) plus state gas for the account (if new) and code bytes (EIP-8037); EIP-8360 TCREATE is CFI for Hegotá. — [EIP-7997](https://eips.ethereum.org/EIPS/eip-7997); [EIP-8038](https://eips.ethereum.org/EIPS/eip-8038); [EIP-8081](https://eips.ethereum.org/EIPS/eip-8081)
- EOF: EIP-7692 (EOFv1 Meta) is Stagnant; EOF is in neither EIP-7773 nor EIP-8081; EIP-8024 (backward-compatible SWAPN/DUPN/EXCHANGE, originally an EOF item EIP-663) ships in Glamsterdam as legacy-EVM opcodes; EIP-8173 "Foundations of EVM Control Flow" is PFI for Hegotá. — [EIP-7692](https://eips.ethereum.org/EIPS/eip-7692); [EIP-7773](https://eips.ethereum.org/EIPS/eip-7773); [EIP-8081](https://eips.ethereum.org/EIPS/eip-8081); 2025 removal report: [CryptoSlate](https://cryptoslate.com/ethereum-drops-eof-from-fusaka-upgrade-after-community-pushback/)
- Blobs/BLOBHASH: no BLOBHASH opcode change found; blob fee floor via EIP-7918 (`BLOB_BASE_COST = 8192` execution gas equivalent per blob); throughput 6/9 → 10/15 (BPO1, 2025-12-09) → 14/21 (BPO2, 2026-01-07); BPO1 fraction 8,346,193. — [EIP-7918](https://eips.ethereum.org/EIPS/eip-7918); [EIP-8134](https://eips.ethereum.org/EIPS/eip-8134); [EF Fusaka announcement](https://blog.ethereum.org/2025/11/06/fusaka-mainnet-announcement)
- Max contract size: EIP-7954 (Glamsterdam SFI, Last Call deadline 2026-11-01) → 65,536 bytes code / 131,072 initcode; EIP-7907 (metering beyond 24 KB at 2 gas/word) is PFI Hegotá; ethereum.org confirms "Maximum contract size rises from about 24 KiB to 64 KiB". — [EIP-7954](https://eips.ethereum.org/EIPS/eip-7954); [EIP-7907](https://eips.ethereum.org/EIPS/eip-7907); [ethereum.org/roadmap/glamsterdam](https://ethereum.org/en/roadmap/glamsterdam/)
- EIP-7825 and batching: cap 16,777,216 execution gas per tx; EIP-8037 adds a separately-metered state-gas reservoir not subject to the 2^24 cap (total `tx.gas ≤ 2^32 − 1`), introduced "allowing for increased throughput and for larger contract deployments without being limited by the single transaction gas limit". — [EIP-7825](https://eips.ethereum.org/EIPS/eip-7825); [EIP-8037](https://eips.ethereum.org/EIPS/eip-8037)
- EF's own developer guidance for Glamsterdam: "Contracts relying on fixed gas stipends, hardcoded gas limits, or assumptions about remaining gas may need changes"; a "repricing impact guide" and the gas-invariants repo exist. — [EF testnet announcement](https://blog.ethereum.org/2026/09/17/glamsterdam-testnet-announcement); [EF 8037/8038 post](https://blog.ethereum.org/2026/11/06/glamsterdam-8037-8038)

### Inferences
- A batch relayer today (Fusaka) is bounded at ~16.7M execution gas per tx: e.g. with a Groth16 verifier (~200–300k gas incl. pairing) plus nullifier/commitment storage (~2 new slots), roughly 40–60 withdrawals per tx is the practical ceiling; after Glamsterdam the execution part stays under 2^24 but each new slot adds ~97,920 state gas drawn from the reservoir, so `tx.gas` must be sized well above 2^24 (up to 2^32−1) to carry the state gas.
- Patterns at risk in a privacy stack: (a) `gasleft()`-based relayer refund/fee logic and fixed-gas external calls (EIP-8038/8037 raise costs non-uniformly); (b) relying on SSTORE refunds to subsidize nullifier set-to-zero patterns (EIP-7778 now, EIP-3298 later); (c) deploying verifier contracts via CREATE2 with cost assumptions (12,000 CREATE_ACCESS + 1,530 state gas/byte); (d) Solidity `ecrecover` on addresses that have code (EIP-8151, Hegotá); (e) any contract that implemented SELFDESTRUCT-based burn semantics (EIP-8246/4758).
- Nothing scheduled changes BLOBHASH or precompile addresses, so KZG/blob-based data posting and existing BN254 verifier addresses (0x06–0x08) remain stable; BN254 gas is untouched by any listed EIP.
